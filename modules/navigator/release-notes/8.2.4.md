# TPS Notebook Navigator 8.2.4

Backward-compatible performance patch. Skip the aggregate Properties count when the navigation pane cannot consume it.

## Scope and compatibility

- Pass the existing navigation-pane visibility predicate to the shared tree hook: dual-pane mode or the single-pane
  navigation view. This is pane visibility, not application focus or document visibility.
- Gate only the all-Properties inventory query. Property trees, root/child ordering, nested rows and file-list pill
  colors remain on their existing calculation paths even while navigation is hidden.
- Keep the existing downstream retained count map. Revealing navigation or enabling Properties/counts reads current
  files and visibility rules, including additions, deletions, hidden folders, frontmatter properties and file tags. A
  Properties-root shortcut remains an aggregate count consumer while navigation is visible.
- No new cache, index, listener, timer, writer, public API, persisted state, setting/default or migration is introduced.
  Minimum Obsidian remains 1.11.0; existing desktop/mobile support and saved settings are unchanged.

## Validation

- Fourteen actual-hook regressions compose the shared tree hook, downstream count hook, file-pill hook and existing file
  finder. The harness preserves React memo/ref/effect dependency semantics; inventories/metadata are synthetic, and
  DOM/paint are outside its scope.
- Eight new cases fail against the unchanged 8.2.3 baseline. Across twenty hidden source-state updates with 1,000 notes
  and a frontmatter visibility rule, the baseline performs twenty inventory queries and 40,000 metadata lookups. The
  candidate performs zero of either.
- Controls cover hidden-to-visible freshness with and without another vault event, retained count-map identity,
  additions/deletions, current folder/frontmatter/tag filters, show-hidden mode, enable/disable transitions, root and
  shortcut-only consumers, nested custom ordering, rainbow colors and file-pill model identity. Twenty unchanged renders
  already perform no inventory or metadata work and preserve their model identities.
- The initial focused run passes 45 tests across five files. Before versioning and again with 8.2.4 metadata, the full
  suite passes 3,321 tests in 284 files under Node 24.19.0. Full ESLint has zero errors and 26 existing warnings. Style
  lint, TypeScript, locale usage/shape, source namespace, artifact identity, operational identity and scoped source/test
  formatting pass.
- Initial production-mode builds used `TPS_NO_DEPLOY=1` for isolated validation. All versioned gates pass. The ordinary
  Test-vault build deployed only the changed `main.js` and `manifest.json`; `styles.css` remained byte-identical. A
  named plugin reload verified 8.2.4 and preserved enabled plugins, saved settings and leaf state.
- A source-attributed installed daily-note trace identified one legitimate coalesced tag-content rebuild followed by an
  unused Properties aggregate inventory. The owning hook has no ordinary file-open/tab listener; this does not
  demonstrate a scan on every tab switch. Tag-tree storage rebuilds are not modified by this patch.
- The separate installed 8.2.3 baseline used an already hidden, narrow single-pane navigation view. Note creation and
  the first body edit each caused two Properties aggregate inventory queries, matched to the unique compiled memo
  callback span. Two later edits and idle controls caused none. Total Navigator inventories were three on creation and
  two on the first edit; other necessary refresh owners remain unchanged by the candidate.
- The baseline restored pass-through methods and preserved all eight active plugins' saved settings/data, runtime
  identities, navigation and leaf state. Its UUID fixture was byte-checked and archived. The host was hidden and
  unfocused; this was finite warm event-driven testing, not physical input or cold application startup.
- The same six-phase installed 8.2.4 comparison made zero Properties aggregate inventories in every phase, removing all
  four baseline queries. Required refresh work remained: one all-files inventory on creation and one Markdown inventory
  on the first body edit. Two later edits and idle remained zero. Pass-through methods were restored; all eight plugins'
  saved settings/data, runtime identities and view state were preserved. The UUID fixture was byte-checked and archived.
- The installed Live Preview daily-note smoke check passed thirteen phases, six tab switches and two remounts. Actual
  Health widgets rendered 24 food rows and 39 activity rows. There were zero phase errors, observed long tasks or
  navigation note-mutation attempts; no all-files inventories and one Markdown inventory on the first activity mount.
  Saved settings/data, active-workout state and original leaf were retained; three UUID fixtures were byte-checked and
  archived. This was a hidden, unfocused warm API flow, not physical input, foreground paint or cold application
  startup.
- The mandatory separate ordinary post-documentation build retains the tested runtime artifact hashes and all eight
  plugins' saved data/settings. Byte identity requires no further reload. Production remains untouched.

## Evidence boundaries

Removing an unconsumed aggregate query is not a complete explanation or fix for multi-second responsiveness. Synthetic
operation counts and hidden warm desktop event traces do not establish physical iPhone, Windows, foreground paint or
production latency. Legitimate storage updates and other required navigation work remain separate owners.
