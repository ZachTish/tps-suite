# TPS Notebook Navigator 4.3.0

## Intent

Make the first-class Types browser behave like a real TPS work surface while preserving its safe virtual-row boundary
and extending it without enabling legacy providers accidentally.

## Changes

- Hydrates task-backed Type entities through GCM's canonical Task API and shows live checkbox state in both
  **Checkboxes** and dynamic Kind collections.
- Re-resolves the entity locator before mutation, uses canonical configured completion when available, validates the
  returned effective state, and rolls optimistic UI back on guarded failure.
- Exposes GCM's full task-line menu through a restricted synchronous item/separator facade for desktop right-click,
  mobile long-press, and the accessible **More actions** button.
- Refreshes task hydration on GCM file-update events even when the Entity Index revision is unchanged.
- Batches cold task hydration across source paths and retains a bounded metadata-keyed LRU. Exact GCM, native vault, and
  Navigator mutation events invalidate affected paths; failed hydration remains retryable.
- Adds opt-in external provider support for Type scopes. Native Type rows remain first and render once; attached-list
  providers remain excluded unless they explicitly set `supportsTypeScope: true`.
- Advances the public API to 2.5.0 with `selectionType: 'type'`, opaque `selectedType`, `supportsTypeScope`, and guarded
  `addSeparator()`.
- Reserves 54 px desktop and 57 px mobile provider-row heights, with 44 px mobile checkbox, open, and More controls.

## Compatibility and migration

- Backward-compatible minor release; no settings or note-data migration.
- Minimum supported Obsidian version remains 1.11.0.
- TPS Global Context Menu 1.15.0 is the tested canonical completion baseline. Older Entity Index v3 builds can still
  populate Types; missing mutation capabilities degrade to display-only.
- Existing external row providers are not queried in Type scopes unless they opt in, so pre-2.5 behavior is preserved.

## Validation

- Focused tests cover structural and dynamic-Kind task hydration, batching/cache reuse and invalidation races,
  failed-read recovery, moved and stale locators, configured completion mappings, effective-state mismatch rollback, GCM
  menu item/separator routing, Type-scope provider isolation, native-first composition, virtualization, and mobile
  targets.
- The complete 2,094-test suite, formatting, ESLint, TypeScript, stylesheet, namespace, artifact, final build,
  test-vault reload, and live task-menu/checkbox/source-line smoke all pass for the released artifact.

## Known limitations

- Type collections remain virtual records: they intentionally do not participate in file multi-select, drag, rename,
  pinning, grouping, or note creation.
- Type-capable external providers can augment an existing indexed Type collection; they cannot define new top-level Type
  collections in this API version.
