# TPS Notebook Navigator 6.2.0

Property names and values can now open matching Markdown notes. For example, the `status` property links to `status.md`, and the `xyz` value of `project` links to `xyz.md`. Matching is case-insensitive and does not require frontmatter on the destination note.

- Enable **Folders & navigation notes → Enable folder, tag and property notes**, with **Names open matching notes** enabled.
- Linked names work in the Properties tree, shortcuts, and the selected list title. Keyboard activation, middle-click, and **Open property note** in the context menu reuse the existing current-tab/new-tab/right-sidebar destinations.
- Row/icon selection keeps normal property filtering and counts. Missing or duplicate filenames do not link. Creation, deletion, rename, and folder moves update the transient lookup live.
- Existing settings keys/defaults, note contents, public API, and upstream isolation are preserved. No migration or property-note template/creation action is added. Minor version chosen for a backward-compatible feature.
- Corrects existing unsafe typings in the GCM property catalog adapter and artifact identity test; valid catalog behavior is unchanged.

## Limitations and handoff

Matching uses a unique whole Markdown basename anywhere in the vault, including hidden/archive folders. Duplicate filenames require disambiguation by renaming; no automatic choice is made. Property values use the existing tree display label, including wiki-link display labels; this is not a new link-target/alias resolver. No note is created or rewritten by opening a property note.

Tested in the test vault and ready for the user's **BRAT pull of exact numeric tag 6.2.0** from `ZachTish/tps-notebook-navigator`. Production was not inspected, installed, or reloaded. User acceptance and production BRAT installation are separate steps.
