# TPS Notebook Navigator 4.1.0

## Intent

Give modular row providers safe, native-feeling actions while keeping mixed GCM and external provider lists responsive
and stable during independent refreshes.

## Changes

- Advances the public Rows API to 2.3.0 with optional synchronous `NavigatorRowDefinition.contextMenu(context)`
  builders.
- Gives providers an immutable row identity and guarded `addItem(...)` callback without exposing Obsidian's host `Menu`
  object.
- Opens populated provider menus from desktop right-click, native mobile `contextmenu`/long-press, and a
  keyboard-focusable **More actions** button.
- Isolates empty, throwing, delayed, Promise-returning, and failed item builders so they cannot open blank menus or
  break the file list.
- Streams independent provider results as each settles, then deterministically recomposes them in configured provider
  order.
- Applies one true 1,000-row ceiling across all providers, with invalid, duplicate, and out-of-scope rows removed before
  that shared budget is spent.
- Retains each unresolved provider's previous rows during same-scope revision refreshes, while a settled empty or failed
  provider immediately removes only its own prior slice.
- Keeps ordinary file navigation and existing GCM task checkbox/focus behavior intact when provider types share the same
  source note.

## Compatibility and migration

- Minimum supported Obsidian version remains 1.11.0.
- Public API version is 2.3.0; the new row action field is optional and backward compatible.
- No settings or note-data migration is required.
- Upstream Notebook Navigator and TPS Notebook Navigator remain co-installable with separate runtime and storage
  identities.
- Built-in GCM task rows do not yet declare row actions themselves; this release provides the generic host capability
  for GCM or any other provider to adopt independently.

## Validation

- Under the required Node 24 runtime, all 183 Vitest files and 2,007 tests passed. Focused coverage includes native
  context-menu routing, guarded action construction, empty/failed provider settlement, per-provider refresh retention,
  delayed priority displacement, the global row budget, combined GCM-plus-external composition beneath one note, and
  release-note version alignment.
- TypeScript, ESLint, Stylelint, Prettier, the TPS source-namespace check, the production build, and generated artifact
  identity checks passed.
- The final production-mode bundle deployed and reloaded only in **Obsidian Plugin Test Vault**. Source and runtime
  artifacts matched byte-for-byte, and the settings surface identified the installed build as 4.1.0.
- A synthetic public provider and real GCM task rows rendered together beneath the same note in the reloaded app.
  Right-click on both the provider title and checkbox, More-button click, Enter, and Space each opened exactly one
  provider menu; executing its action showed the expected notice without changing the selected file or opening a note.
- Real GCM title activation opened `Inbox/Synthetic Task Sink.md` at zero-based cursor line 5 (display line 6), and
  checkbox mutation completed then reopened the exact fixture task. The fixture content and original task-row settings
  were restored.
- During a deliberately delayed same-scope refresh, the prior external row remained visible and was replaced by the
  fresh row after settlement. After switching to `Examples/TPS Base Filter Lab` before another delayed query resolved,
  only that scope's source path rendered; the stale Inbox row did not return.
- Native mobile long-press generation could not be exercised on the desktop test host. The shared `contextmenu` route,
  explicit More-button route, 40 px mobile controls, and keyboard access were covered; physical-device long-press
  remains a stated limitation rather than an inferred pass.
- Production was not accessed.

## Known limitations

- Built-in GCM task rows retain checkbox and exact-line activation but do not show **More actions** until GCM supplies a
  `contextMenu` builder through the generic API.
- Provider rows remain transient records; they do not participate in file multi-select, drag, rename, persistence, or
  file indexes.
- Provider queries remain limited to source files already represented in the current navigator list.
- Native long-press generation varies by mobile OS/WebView; the host listens to the standard `contextmenu` event and
  also provides the explicit touch-sized **More actions** button.
