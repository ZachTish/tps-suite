# TPS Notebook Navigator 6.4.2

Fix right-click Rename note immediately after creation. The old filename-only route could turn `Untitled.md` into `New name.md` while leaving `title: Untitled`, because its follow-up title synchronization depended on Controller background automation. That automation is intentionally disabled on User/mobile devices.

Ordinary note renames now use GCM's existing explicit title writer when available. Inline rename, the dialog fallback and manual-sort keyboard rename share that path. The write reads current note source even when metadata has not arrived; GCM's Auto-rename preference and filename ownership/collision checks determine the resulting filename. Inputs prefill from the title when available. A cancelled, rejected or failed property write never falls through to filename-only renaming.

Separately configured non-title display fields, explicit folder-note detachment, non-Markdown resources and standalone Navigator operation retain their own paths. No setting, schema, migration, watcher, retry or automatic repair was added. Existing mismatched notes are not remediated. This is a backward-compatible patch, tested with GCM 3.3.3; no new GCM version is needed.

- Actual UI: New note → dismiss new-note preview → right-click the new Untitled row → Rename note → enter name. Navigator displayed `Navigator right-click verified`, and source verification confirmed the matching filename and title.
