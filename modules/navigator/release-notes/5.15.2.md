# TPS Notebook Navigator 5.15.2

This backward-compatible patch makes property key rows consistently represent fields that exist without a value.

## Fixed

- Selecting a property key now returns only notes where that field exists without a value, even when the descendant
  toolbar setting is enabled.
- Property-key counts, shortcut counts, frequency ordering, and active-note reveal use the same empty-value scope.
- Modifier-clicking a property key adds `.key=` to Filter Search so multi-select keeps the empty-value meaning. The
  existing `.key` syntax remains the broader key-presence filter.
- Dropping Markdown notes onto a property key writes the key with a `null` frontmatter value, serialized by Obsidian as
  a bare YAML field such as `description:`. Existing scalar values, including `true`, are replaced.
- Child property-value rows continue to select and assign their exact values. The top-level Properties collection
  continues to represent the full configured property catalog.

## Compatibility

- No settings or note migration is required. TPS Notebook Navigator remains co-installable with upstream Notebook
  Navigator.
- Saved searches that already use `.key=` now use its explicit exact-empty meaning. Use `.key` when the intended search
  is the broader “field exists” match.
- Minimum supported Obsidian version: 1.11.0.

## Validation

- The final focused property-root/search/reveal regressions passed (120 tests), and the complete declared suite passed
  (237 files, 2,713 tests).
- TypeScript, ESLint (zero errors; 19 existing warnings), Prettier, Stylelint, locale consistency, TPS namespace,
  operational identity, and generated-artifact checks passed. A separate final production-mode build deployed version
  5.15.2 to the test runtime, whose `main.js`, `manifest.json`, and `styles.css` matched the source artifacts byte for
  byte.
- After reloading the test-vault plugin, live UI QA confirmed that a property key shows only the empty-valued note, its
  child value shows only the valued note, and opening Filter Search from the key produces `.description=`. The
  executable drop regression confirmed that assigning a key replaces `true` with a `null` frontmatter value. The
  temporary profile setting was restored and all three synthetic QA notes were moved to `_archive`.
- Production was not accessed or modified.
