# TPS Notebook Navigator 5.23.1

This patch fixes a cold-start race that could leave existing Core Daily Notes absent from Notebook Navigator's calendar
until another file or provider event happened.

- Daily Notes mode now subscribes to Obsidian's public metadata-ready event before requesting an immediate startup
  recheck.
- The existing debounced calendar invalidation path clears cached missing-day results and re-resolves the current
  visible dates after metadata becomes authoritative.
- Listener cleanup remains tied to the mounted calendar and the extra readiness subscription is inactive in Notebook
  Navigator's independent calendar-note mode.
- No notes, settings, IndexedDB schema, or public TPS API are changed.

Validation passed 256/256 test files and 2,936/2,936 tests, followed by the mandatory separate production build. After a
cold reload of Obsidian 1.13.7 in the isolated test vault, the calendar immediately opened both a zero-byte Daily Note
and a populated Daily Note at their configured paths without a creation prompt; their bytes and the Daily Note file
count were unchanged. Minimum supported Obsidian: 1.11.0. Known limitation: legacy Daily Note identity supplied only by
an enabled-but-incompatible third-party provider remains governed by that provider's own contract.

Tested in the isolated Obsidian Plugin Test Vault. Production was not accessed.

This release is ready for the user's BRAT pull.
