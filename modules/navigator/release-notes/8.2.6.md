# TPS Notebook Navigator 8.2.6

Ordinary **Rename note** now opens Obsidian's native file rename dialog for the selected file. Navigator stops building its own title input; Obsidian handles filename validation, conflicts, cancellation and link updates. Committed filename-to-title propagation belongs to GCM's existing rename owner when its title-sync setting is enabled.

This is a backward-compatible patch. Minimum Obsidian remains **1.11.0**. Tested in **Obsidian Plugin Test Vault** on macOS with Obsidian **1.14.4** and GCM **8.1.1**, and ready for the user's BRAT pull. No production installation is claimed.

## Changes

- The list context menu, configured Enter/F2 rename action, modal fallback and manual-sort keyboard action share the exact-file native prompt. They do not issue an active-note command or focus/scroll a row to create a custom input.
- Opening the dialog does not read note source, enumerate files or write frontmatter. The prompt's Promise signifies dialog opening, not a committed rename.
- Ordinary Markdown drawing Rename uses the same native dialog and filename/extension validation.
- A separately configured non-title display property, resolved through the existing ordered `frontmatterNameField` list, keeps its property editor. Folder renaming, folder-note detachment, direct programmatic property editing and programmatic filename/resource renames retain their existing routes.

No settings, defaults, persisted state, namespace, queue, timer, cache, listener, migration or repair behavior changes. All fork identities remain TPS-namespaced.

- Focused rename coverage passes **31/31**. Fifteen new real-service/ListPane regressions cover exact inactive targets, missing metadata, configured-property exceptions, unsupported/failing prompts, cancellation-equivalent prompt resolution and repeated native opens with zero source I/O, inventories, frontmatter writes or custom editors. Against unchanged 8.2.5, ten new checks fail and five controls pass; host/core dialog boundaries are mocked in these source tests.
- The final versioned full suite passes **3,345/3,345 in 286 files** under Node **24.19.0**. Full ESLint has zero errors and the same 26 existing warnings. Style lint, namespace, artifact/operational identities, scoped formatting and TypeScript/string/locale checks pass.
- The mandatory separate ordinary build deployed only to the test vault. Targeted reload verified Navigator **8.2.6**, GCM **8.1.1** and all eight active TPS consumers, with background automation disabled.
- Actual Navigator context-menu **Rename note** displayed the core **Note title** dialog with the filename selected. Save committed one core filename rename and one GCM native-record title update in the User role, with no custom title action. Title and body remained correct. Combined-consumer counts were **4 raw reads, 8 cached reads, 2 inventories and 1 atomic process**; downstream consumers account for these operations, while Navigator prompt opening itself performs no source work.
- GCM title Save/Cancel, detached-window cancellation, untouched keyboard focus/blur and new `Untitled.md` propagation also passed. New-note creation used the vault API, followed by actual core dialog keyboard input. Instrumentation was removed, the original note/dashboard restored and owned fixtures archived byte-identically. Runtime settings were unchanged apart from Navigator's existing `lastShownVersion` acknowledgement. No production data or outbound automation was used.

## Limitations

`fileManager.promptForFileRename` is an internal Obsidian method, verified in installed 1.14.4 and feature-detected. An unavailable or failed prompt shows a Notice without a custom fallback. Physical iPhone and minimum-version acceptance remain pending. No overall latency or production speed claim follows from these checks.
