# TPS Notebook Navigator 4.4.0

## Intent

Give GCM tasks the same controls and state fidelity everywhere they render, close the remaining bundled drag-and-drop
accessibility namespace collision with upstream Notebook Navigator, and make future upstream conflict discovery
repeatable and read-only.

## Changes

- Adds the full guarded GCM task-line menu to tasks attached beneath ordinary note rows. Desktop right-click, mobile
  long-press, and the accessible **More actions** button now match task-backed Type rows.
- Re-resolves the current GCM Task and Task Lines APIs when an action opens, tracks capability replacement/removal, and
  omits stale or empty menus rather than acting on an old plugin object.
- Re-resolves tasks before source activation and shows a visible warning when the current task cannot be opened.
- Renders provider-supplied checkbox markers verbatim, including non-binary working and holding states, and includes the
  current marker in an accessible state label. Optimistic complete/reopen actions still use the binary fallback until
  the refreshed source state arrives.
- Namespaces `@dnd-kit/core` described-by and live-region ID prefixes only at the TPS bundle boundary. The final
  artifact gate rejects either upstream prefix, keeping inherited drag-and-drop source merge-friendly while preventing
  duplicate accessibility DOM IDs beside upstream Notebook Navigator.
- Adds `npm run upstream:audit -- <ref>`. The command resolves the merge base, reports fork/upstream/overlap counts,
  simulates `git merge-tree`, and classifies exact generated, documentation, source, test, and other conflicts without
  fetching, merging, updating refs, or changing the worktree.

## Compatibility and migration

- Backward-compatible minor release; no settings, public API, or note-data migration.
- Public API remains 2.5.0. Existing providers that omit `indicator.marker` keep the normal blank/check fallback.
- Minimum supported Obsidian version remains 1.11.0.
- TPS Global Context Menu 1.15.0 remains the tested task completion and Task Lines baseline. Missing optional mutation
  or menu capabilities disable only that control while ordinary Navigator behavior remains available.

## Validation

- Focused tests cover attached-row menu construction and stale failure, current GCM API replacement, `taskLines`
  capability hot-swaps, activation failure notices, custom-marker rendering/accessibility, dnd-kit dependency transform
  boundaries, artifact enforcement, and upstream-audit Git-state immutability.
- The complete 198-file, 2,104-test suite, formatting, ESLint, TypeScript, stylesheet, source namespace, final artifact,
  production build, and test-vault reload pass for the released artifact. Live UI smoke confirms the 4.4.0 release,
  first-class Types navigation, and simultaneous upstream/TPS command registration; attached task actions remain covered
  by focused integration tests without changing the test vault's disabled task-row setting.
- The read-only audit of `upstream/3.3.1-2` reports 195 fork files, 83 upstream files, 24 overlaps, and the exact five
  conflicted files (13 conflict markers) without changing refs, objects, status, or the worktree.

## Known limitations

- GCM task actions require the optional current `tasks.parseLine` and `taskLines` capabilities. Compatible older GCM
  builds remain usable but do not show the attached-row action menu.
- The upstream audit analyzes an already available ref; it intentionally does not fetch or perform the merge.
- External providers can augment existing Type collections but still cannot define new top-level Type collections in
  public API 2.5.0.
