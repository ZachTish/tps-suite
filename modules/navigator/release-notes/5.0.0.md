# TPS Notebook Navigator 5.0.0

## Intent

Make **Types** describe the structural shape of vault content—not a frontmatter taxonomy—and give every Type result the
same clean, familiar visual language as the normal file browser.

## Changes

- Replaces the nested frontmatter-driven Kinds branch with one flat built-in catalog: Notes, Checkboxes, Bullets,
  Headings, Bases, Canvas, Drawings, PDFs, Images, Audio, and Video.
- Classifies each supported vault file into exactly one file-backed Type. Excalidraw Markdown and native Excalidraw
  files belong to Drawings instead of Notes; extension matching is case-insensitive.
- Sends Notes, Bases, Canvas, Drawings, PDFs, Images, Audio, and Video through the ordinary Navigator file pipeline so
  they inherit native rows, icons, properties, previews, sort, grouping, search, selection, menus, drag behavior, and
  opening behavior.
- Restyles Checkboxes, Bullets, and Headings as native-looking file rows with a restrained structural icon or live task
  checkbox, source-path context, exact-line activation, accessible actions, and mobile-sized touch targets.
- Keeps file-backed Types available without TPS Global Context Menu. Only the three exact-line collections depend on the
  generic GCM Entity Index, with cache-aware refreshes and guarded recovery from snapshot failures.
- Preserves live file order for move, drag, and delete selection recovery inside file-backed Types, avoids repeated
  whole-vault scans on unrelated metadata changes, and suppresses cached sticky headers in zero-result views.
- Advances the public API to 3.0.0 because discoverable and navigable Kind collections were removed. Deprecated Kind-id
  builders/parsers remain only for source and stale-state recognition; active Type validation, restore, history, menus,
  and navigation reject Kind ids immediately.
- Gives every fixed file-backed Type its own optional sort and appearance overrides, native toolbar controls, public
  list presentation snapshot, and metadata-aware regrouping. Exact-line/provider Type presentation remains
  owner-controlled.

## Compatibility and migration

- Major plugin/API release because the public Type catalog no longer includes frontmatter Kind descriptors.
- Minimum supported Obsidian remains 1.11.0; desktop and mobile remain supported.
- Existing provider-owned Type collections and ordinary row providers remain available. File-backed Type IDs are new
  fixed catalog entries; stale saved `kind:*` selections fall back safely.
- Optional `typeSortOverrides` and `typeAppearances` records are created only when a file-backed Type presentation
  changes. Existing settings inherit normal defaults without migration; note content and frontmatter are untouched.

## Validation

- All 218 Vitest files and 2,380 tests pass. TypeScript, ESLint (zero errors; 18 intentional deprecated-compatibility
  warnings), Prettier, stylesheet lint, CSS namespace, operational-identity, artifact-identity, and production-build
  gates pass for the versioned candidate.
- Live Obsidian 1.12.7 test-vault QA after reload confirmed the complete flat catalog with no Kinds branch; native Notes
  and Bases; native-styled Checkboxes and Bullets; exact-line source activation; a clean zero-result Drawings state; and
  co-installation with upstream Notebook Navigator.
- Source and deployed test-runtime artifacts are byte-identical. Runtime-owned `data.json` retained the same inode,
  size, modification time, and SHA-256 hash across the final build and reload. Production was not accessed or changed.

## Known limitations

- Checkboxes, Bullets, and Headings require a compatible TPS Global Context Menu Entity Index. File-backed Types do not.
- Exact-line and external provider rows are transient source locators, so they do not participate in native `TFile`
  multi-select, pinning, drag, rename, or persisted selection.
- YAML-backed manual ranking cannot write a rank to non-Markdown Types; their filename, title, created, and modified
  sorts continue to work normally.
- Deprecated Kind-id helpers only construct or parse legacy IDs for migration. Frontmatter groupings belong under
  Properties or a separate relational entity index.
