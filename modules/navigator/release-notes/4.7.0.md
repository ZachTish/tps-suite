# TPS Notebook Navigator 4.7.0

## Intent

Let integrations survive a TPS Notebook Navigator-only reload without polling plugin internals, retaining a disposed
API, or persisting provider callbacks inside Navigator.

## Changes

- Advances the additive public API from 2.7.0 to 2.8.0.
- Adds `tps:notebook-navigator-api-changed`. It announces a fully initialized API and announces unavailability before
  the current Rows and Types registries are disposed.
- Adds `tps:notebook-navigator-api-request`. A late-loading integration supplies a guarded synchronous responder and
  receives the current state point-to-point instead of causing a global rebroadcast.
- Publishes immutable lifecycle payloads with source identity, timestamp, availability, plugin version, API version, and
  the current nullable API instance.
- Ignores malformed requests and isolates throwing or rejected consumers so they cannot interrupt startup or shutdown.
- Documents an idempotent registration pattern that releases the old provider handle and binds to each replacement API.
- Strengthens the final co-install artifact gate: source and generated CSS must keep the TPS-only Style Settings block
  ID, and the bundle must reject the actual upstream shortcut drag MIME.

## Compatibility and migration

- Backward-compatible minor release; no settings or note-data migration.
- Existing API 2.x consumers keep their current behavior. Automatic reload recovery is opt-in through the new lifecycle
  events and request handshake.
- Lifecycle state, responders, API objects, and provider registrations are runtime-only and are never persisted.
- Minimum supported Obsidian version remains 1.11.0.

## Validation

- Focused tests cover early unavailable requests, late available requests, immutable payloads, point-to-point responses,
  idempotent startup/shutdown, exact unavailable-before-disposal ordering, API replacement, malformed requests, throwing
  and rejected callbacks, and automatic provider reacquisition.
- Isolation fixtures reject the upstream Style Settings ID in either source or generated CSS and reject
  `application/x-notebook-shortcut` in the final bundle.
- The complete 205-file, 2,182-test suite, formatting, ESLint, TypeScript, stylesheet, source namespace, final artifact,
  and production-mode build gates pass for the released artifact.
- The contained build atomically deployed only `main.js` and `manifest.json` to the isolated test vault; `styles.css`
  was already byte-identical, and the runtime settings file was preserved by deployment.
- Obsidian 1.12.7 live QA observed `request available → changed unavailable → changed available` across a TPS-only
  disable/re-enable, confirmed a distinct replacement API instance, and received the final `4.7.0` / API `2.8.0` payload
  after an app reload.

## Known limitations

- An integration must subscribe and implement the documented rebinding pattern to recover automatically. A consumer that
  intentionally retains only its original API object still owns that stale reference.
- The lifecycle handshake coordinates in-memory plugin instances only; it does not persist or replay provider
  definitions.
- Optional GCM-backed Types and task controls still require a structurally compatible TPS Global Context Menu API and
  fail closed when that integration is absent.
