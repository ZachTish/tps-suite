# TPS Notebook Navigator 5.2.0

Released: 2026-08-02

Minimum Obsidian version: 1.11.0

Public API version: 3.1.0

## What changed

- Adds a compact **Type order** selector to **Reorder navigation** with **Default order**, **Name: A to Z**, **Name: Z
  to A**, **Most items first**, **Fewest items first**, and **Manual order**.
- Keeps alphabetical and quantity modes live as the current visibility-filtered Type catalog and counts change. A real
  zero remains sortable, while provider Types that intentionally publish no count stay after counted Types.
- Adds accessible up/down controls to every Type row and includes Types in desktop drag ordering. Either action switches
  the collection to **Manual order** and persists the requested sequence on the first move, including newly discovered
  provider Types.
- Preserves temporarily unavailable provider Type ids in their saved slots so plugin load order or a temporary provider
  outage does not silently rewrite a manual layout.
- Uses touch-sized controls and handle-only drag targets on mobile. Narrow desktop panes prioritize readable labels and
  reveal row arrows on hover or keyboard focus.

## Compatibility and migration

- This is a backward-compatible feature release. The provider-neutral Type catalog and public API remain unchanged at
  API 3.1.0.
- Existing settings need no migration. Missing order fields resolve to **Default order**; one-way upstream settings
  imports cannot overwrite the TPS-only mode or manual sequence.
- The minimum supported Obsidian version remains 1.11.0.

## Known limitations

- Quantity order is intentionally live, so a Type can move when its count changes.
- Provider Types that do not publish a count cannot be ranked numerically and remain after all counted Types in either
  quantity direction.
- Very narrow desktop panes temporarily hide counts to leave room for readable labels and ordering controls.
- Mobile markup, touch targets, handle-only drag wiring, and responsive CSS are regression-tested, but this release was
  not automated on a physical iOS device.

## Validation

- Focused ordering, hook, and component coverage passes 13 tests across 3 files, including natural label ordering, both
  quantity directions, zero-versus-unknown counts, manual persistence, temporarily unavailable provider anchors,
  first-move persistence for newly discovered Types, selector options, counts, and arrow endpoints.
- Full suite: 222 test files and 2,425 tests passed.
- TypeScript, ESLint, Prettier, stylesheet, TPS source-namespace, operational-identity, artifact-identity, and Git diff
  checks passed. ESLint reported only the repository's 18 existing compatibility-path deprecation warnings and no
  errors.
- The final production-mode build deployed the byte-changed plugin artifact to the isolated test runtime. Source and
  runtime `main.js`, `manifest.json`, and `styles.css` matched byte for byte at version 5.2.0.
- Obsidian 1.12.7 was reloaded in **Obsidian Plugin Test Vault**. The 5.2.0 release dialog appeared, and live desktop UI
  QA confirmed the Type-order selector, readable narrow-pane labels, and per-row arrows without changing the manual
  sequence.
- The test runtime `data.json` inode was preserved across deployment. Plugin startup recorded the displayed 5.2.0
  release and normalized the two new fields to their non-destructive defaults (`catalog` and an empty manual order). No
  production vault was inspected or changed.
