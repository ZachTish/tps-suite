# TPS Notebook Navigator 7.0.10 — Faster ASCII folder-note lookup

Navigator skips Unicode NFC normalization when comparing ASCII frontmatter keys during folder-note title lookup. ASCII is already NFC. Unicode keys still normalize before case folding, and the first matching key still wins. This removes repeated normalization work from list rendering without changing settings, note data, or the folder-note rules.

This is a backward-compatible **patch**. Minimum Obsidian remains **1.11.0**. Tested in **Obsidian Plugin Test Vault** and ready for the user's BRAT pull; production has not been modified.

## Validation

- Regression tests cover duplicate-case ordering, Unicode equivalence, 120 repeated sibling scans, and a folder-note title added then removed. All **3,237** tests in **277** files pass; TypeScript and formatting checks pass. ESLint reports zero errors and 24 pre-existing advisory warnings.
- In a test-vault folder selection with the changed code, the expected file list rendered. A temporary observer counted **zero** ASCII NFC calls from Navigator and **76** from Obsidian core. The observer was removed after the capture.
- The complete consumer suite remained enabled. The test runtime was built and the named plugin was reloaded. Its `data.json` SHA-256 stayed `ae19116381faf6c9eac40db64a499ce4eb29bdab7d82f3dad3f083433a31fe3f` across deployment. Dismissing the normal What's New notice then recorded `lastShownVersion: 7.0.10` in runtime-owned data. The 12 synthetic QA notes were moved directly to `_archive`, with all bytes checked after the move.
- A prior production CPU profile of Navigator 7.0.8 identified frontmatter-key normalization as a repeated cost during list rendering. The installed test-vault operation count supports the targeted correction, but this release does not establish a production or physical-iPhone latency number.
