# TPS Notebook Navigator 8.0.0 — Whole-note navigation and creation

Navigator now creates complete notes, Bases and Canvas files through its own New action. Line Type selections and Filter Search results cannot create checkboxes, bullets, headings, code blocks, callouts, blockquotes, tables or web-link fragments. The built-in GCM task-row provider and task-line property drop route are removed. Note task counts and progress remain read-only displays; Health's read-only Daily Macros and Activity widgets remain external consumers.

The TPS integration settings destination now has two groups: **File types → Show File types** and **One-way setup → Import upstream Notebook Navigator settings**. General is still the default settings route. There is no nested disclosure or new persisted UI state; the native and older/mobile settings renderers expose the same controls. Saved architecture, line-creation and attached-task-row keys remain readable for compatibility, but loading or importing settings forces native records and disables line-Type navigation and built-in task rows. Existing notes receive no migration or background repair.

External row and Type providers retain their APIs and own any actions attached to their rows. Navigator's dormant GCM task adapter permits a task-line checkbox or menu action only when GCM explicitly reports `supportsTaskLineMutation: true`; GCM 6.0.0 reports false. Whole-note property drops still use Obsidian frontmatter. Configured list values append without replacing existing entries, while non-Markdown asset companion properties are not written. The removal of first-party line creation and task-row settings is a **major** version. Minimum supported Obsidian remains **1.11.0**.

## Validation

Navigator delegates created-note presentation to GCM's shared Preview/Open/Stay preference and offers no custom editable hover card. Toolbar creation supplies the actual click and connected button to GCM so Preview can use Obsidian's core Page Preview; commands and other creation routes still use the same saved preference. GCM 6.0.0 supplies the core preview route and native mobile editor fallback.

- Focused tests cover rejected line-Type creation, zero built-in GCM rows, no task-line drop listener, zero GCM mutation/menu calls when task-line mutation is disabled, and whole-note frontmatter assignment that appends configured lists without GCM companion writes.
- All **3,209 tests in 273 files** pass. TypeScript, locale usage, stylelint, TPS namespace, artifact identity and operational-identity checks pass. ESLint has zero errors and 26 existing advisory warnings. Changed source and metadata pass targeted Prettier; repository-wide Prettier has pre-existing differences outside this change.
- The production-mode 8.0.0 build deployed to the Test vault and the plugin was explicitly reloaded. In Obsidian 1.14.4, Navigator's toolbar New note opened a visible core Page Preview anchored to the button; clicking its body entered Obsidian's editor and a typed change persisted to the new note while the previously open note stayed unchanged. A separate GCM Open test from a Reading leaf reached Editing mode. Original preferences were restored and synthetic notes were archived directly from Inbox. The final source assets match the installed Test runtime hashes below.

Physical-iPhone behavior has not been tested. Native Page Preview requires Obsidian's core Page Preview plugin to be enabled. External providers are responsible for their own row actions; this version does not turn their callbacks into Navigator-owned writers. This release is tested in the Test vault and ready for the user's BRAT pull; production installation is separate.
