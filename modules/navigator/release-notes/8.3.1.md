# TPS Notebook Navigator 8.3.1

Properties **Frequency high to low** and **Frequency low to high** now use the same unique-note count displayed beside each property label. The previous comparator counted only notes without an indexed child value, incorrectly placing smaller numeric fields above properties such as `kind` and `status`.

This backward-compatible **patch** retains minimum Obsidian **1.11.0**. Tested in **Obsidian Plugin Test Vault** on macOS/Obsidian **1.14.4**, ready for the user's BRAT pull. No production installation is claimed.

## Configuration and scope

- Uses existing `node.notesWithValue.size` from the scoped property tree. No additional file reads, inventories, settings, schema, defaults or migration.
- Existing selection/profile visibility, alphabetical/manual ordering and per-property child-sort overrides remain authoritative. File types already sorts using its displayed count and is unchanged.
- No new cache, watcher, timer, writer, repair or background work. Settings navigation and menu layout are unchanged.
- Shortcuts remain stored per vault profile in normal plugin settings, with the existing external-settings refresh. This release does not change syncing or establish the cause of the reported phone discrepancy.

## Validation

- **11/11 new regressions** cover numeric/string/list values, deduplicated memberships, empty/zero counts, both frequency directions, alphabetical/manual modes, selected-folder scope, disabled count consumers, changed memberships and unchanged/event bursts. Three baseline failures reproduce the displayed-count mismatch.
- Twenty unchanged rerenders and fifty file-version updates make **zero raw/cached reads, writes, inventories, indexed lookups or settings calls** for the global comparator. A scoped three-note case makes exactly **three indexed lookups**, with zero inventories. Source tests execute the real hooks/tree using retained memo/ref semantics, mocked host services and suppressed effects; counts apply to these owners, not the entire installed pipeline.
- **62/62 focused checks in five files** and the final versioned full suite: **3,414/3,414 tests in 289 files**, Node **24.19.0**.
- Full ESLint: zero errors, the existing 26 warnings. Style lint, namespace, artifact/operational identity, scoped source/test formatting, TypeScript and string/locale gates pass. Separate ordinary final build deploys only to TEST.
- Targeted TEST plugin reload verifies **8.3.1**, GCM **8.2.0**, and all eight active TPS consumers enabled.
- Installed foreground UI uses the actual Properties sort menu in both directions. Descending shows `kind` **4,134**, `quantity` **3,633**, `status` **324**, then `scheduled` **318**. Ascending begins with zero-count labels, then one-count labels. The prior installed build placed `quantity` above `kind`, reproducing the reported defect.
- Test sort preferences and expansion/search presentation are restored through their existing owners. All recorded TPS runtime data hashes match baseline; Navigator matches after normalizing only its existing `lastShownVersion` acknowledgement. No runtime data files are manually overwritten, no notes are created or changed, and outbound automation and production files are unchanged.

## Limits

Physical iPhone presentation, minimum-version acceptance and production installation remain pending. Installed operation counts and end-to-end latency were not measured; no startup or navigation-speed claim is made. The phone's received shortcut settings and actual sync configuration remain unverified.
