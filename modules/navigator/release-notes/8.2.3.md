# TPS Notebook Navigator 8.2.3

Backward-compatible performance patch. The aggregate Tags count no longer scans the vault when no visible navigation
count consumes it.

## Scope and compatibility

- Skip the existing all-Tags file query while navigation is hidden in single-pane mode, Tags are disabled, or note
  counts are disabled. The guard exactly matches the existing downstream count consumer.
- Reuse the existing retained count map while hidden. Revealing navigation or enabling Tags/counts invalidates the
  guarded memo and queries current files.
- Visible aggregate counts retain the existing file finder and visibility rules: tagged and untagged Markdown notes,
  hidden folders, frontmatter properties and hidden file tags. Folder/property counts and descendant toggles are
  unchanged.
- Visibility means the navigation pane's existing UI state, not browser-window focus or document visibility. A desktop
  dual-pane view retains visible-count behavior.
- No new cache, index, timer, listener, writer, public API, setting/default, persisted state or migration is introduced.
  Minimum Obsidian remains 1.11.0; existing desktop and mobile support is unchanged.

## Validation

- Eleven new regression cases execute the actual count hook and file finder. The harness retains React memo/ref/effect
  dependency semantics; the Obsidian inventory and metadata facade is synthetic, and DOM/paint are not measured.
- Before the source change, seven of the initial nine cases failed. Hidden navigation, disabled Tags and disabled counts
  each enumerated the 1,000-note inventory twenty times across twenty version bursts.
- The guarded version performs zero inventory and metadata reads in those unconsumed modes. Controls cover retained map
  identity, hidden-to-visible catch-up, enabling without another vault event, visible stable renders, create/delete
  changes, hidden folder/frontmatter/file-tag rules and aggregate tagged/untagged counts with descendant toggles.
- The focused run passes 27 checks across four files, including adjacent existing count, tree-section and folder-source
  tests. Scoped ESLint has zero errors and only the existing explicit-version dependency warning; source/test formatting
  and `git diff --check` pass.
- All 3,307 tests in 283 files pass under Node 24.19.0 after generating this worktree's artifacts. The first unbuilt
  full-suite run passed 3,305 tests; its two identity failures required the absent generated `main.js`, not a runtime
  correction.
- Full ESLint reports zero errors and 26 existing advisory warnings. Style lint, TypeScript (`--noEmit --skipLibCheck`),
  locale usage/shape, source namespace, generated-artifact identity and operational-identity checks pass.
- Initial artifact validation was build-only with `TPS_NO_DEPLOY=1`. The separate final production-mode build then
  deployed only byte-changed `main.js` and `manifest.json` to the exact Test-vault runtime; `styles.css` stayed
  byte-identical. Runtime `data.json` was byte-identical before and after, and a targeted reload confirmed 8.2.3.
- The installed before/after probe used the existing narrow single-pane `show-files` view with Tags and counts enabled.
  In 8.2.2, synthetic note creation and the first body edit each caused one aggregate Tags inventory query, attributed
  to the exact `Qfe` count hook → `fT` file-finder memo stack. Both queries were zero in 8.2.3. The two later body edits
  and idle controls were already zero in 8.2.2; this is not an every-edit scan claim. Whole-Navigator inventory calls
  fell from four to three on creation and two to one on the first edit; the remaining refreshes were unchanged.
- Both installed count probes restored their pass-through methods and retained settings, saved data and navigation
  state. Their synthetic fixtures were byte-checked and moved directly to `_archive`. After reload, the existing
  responsive layout naturally settled to its narrow single-pane fallback before the comparison; no UI command, settings
  override, scope change or selection mutation was used to force that state.
- The installed daily-note check with GCM 7.3.10 and Health 4.2.4 passed thirteen phases, including six repeated tab
  switches and two remounts. Actual Health macros/activity Live Preview widgets remained observed and connected. There
  were zero navigation mutation attempts, phase errors, Health render errors or observed long tasks. Settings and
  active-workout state were unchanged; all three display fixtures were byte-checked and archived.
- These installed checks used a hidden, unfocused desktop host and warm API-driven navigation, not cold application
  startup or physical input/paint. Reading-mode rendering, implicit daily-note recognition, provider actions and
  food/activity editing were not exercised. A final documentation-only rebuild preserved the tested artifact hashes and
  made no further runtime changes.

included; production installation remains the user's separate BRAT pull.

## Evidence boundaries

Operation counts demonstrate removal of an unused vault scan, not a complete explanation or fix for multi-second
responsiveness. The combined installed profile used a hidden, unfocused desktop host and captured no long tasks;
minified React work must not be attributed wholesale to Navigator's own logic. Physical iPhone, Windows and production
input latency remain unverified. Production installation is a separate, user-owned BRAT pull.
