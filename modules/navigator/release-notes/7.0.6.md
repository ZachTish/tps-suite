# TPS Notebook Navigator 7.0.6

Backward-compatible file-type catalog performance and freshness fix. Minimum Obsidian: 1.11.0. Tested in Obsidian Plugin Test Vault and ready for the user’s BRAT pull; not installed in production by the development agent.

## Changes

- File create, rename and delete batches classify only affected live files. The existing snapshot is rebuilt in one record pass per batch, with one sort per changed bucket and shared immutable records for unaffected files.
- Folder descendants, overlapping events, extension changes and rapid same-path replacements use the final live vault state. Initial subscription and re-enable still build a full snapshot.
- The store now owns drawing-frontmatter invalidation. Ordinary metadata changes are no-ops; actual Notes/Drawings changes use the existing batch. The listener and pending paths are released when disabled or no longer subscribed.
- No new persisted state, file index, timer, settings, API, migration, body reads or note writes. Existing file-type classification and sorting remain authoritative.

## Validation

- Before the correction, 10 focused assertions failed against the released source; all 28 focused store, catalog and TypesAPI tests now pass.
- One rename among 1,000 notes requires one classification lookup and zero vault enumerations. A 1,000-rename burst among 10,000 notes requires 1,000 lookups and one publication.
- A burst of 1,000 unchanged metadata events performs zero lookups, vault enumerations, scheduled timers or publications.
- Regressions compare incremental results with the unchanged full snapshot builder across folder moves/deletion/recreation, extension transitions, drawing flags, cold metadata, stale events and mixed batches. Lifecycle cleanup and immutable snapshots are covered.
- Node 24.19.0: all 3,202 versioned tests in 275 files passed. Full ESLint has zero errors and the existing 24 advisory warnings. TypeScript, locale, formatting, namespace, artifact and operational-identity checks passed.
- The separate final production-mode build deployed byte-changed main.js/manifest.json to the test vault. A named plugin disable/loadManifest/enable verified installed 7.0.6. The final documentation rebuild was byte-identical; source and test runtime hashes match.
- Before-change installed evidence with GCM 3.6.9 unchanged: one actual Rename action on 7.0.5 saved in 79.4 ms, followed by 10,574 metadata accesses during settling. The catalog samples showed the full Markdown classification pass; this post-save work must not be attributed to the save duration itself.
- Repeating the actual foreground Navigator right-click → Rename action on 7.0.6, with GCM held at 3.6.9, reduced post-save metadata accesses from 10,574 to 174 (98.4%). Save duration remained comparable (79.4 vs 81.7 ms). Both runs had one modify/rename/completion event, correct title and filename, preserved body, and no observed long tasks or outside note mutations. These are single operation samples, not physical click-to-paint or native-parity measurements.
- A separate installed check reproduced the old freshness defect, then verified Notes → Drawings → Notes as drawing frontmatter was added/removed on 7.0.6. Its body was preserved.
- Instrumentation, original note/search state and QA fixtures were restored/archived. The update notice advanced only Navigator’s existing lastShownVersion from 7.0.5 to 7.0.6; all other Navigator settings and six other saved plugin settings remained unchanged. The rename probe’s settingsUnchanged flag is false solely because the notice was dismissed during setup.

## Limits

The snapshot still walks its existing records once per file-event batch and sorts changed buckets. This removes redundant classification and vault enumeration; it does not remove every post-rename/list refresh. No production, cold-start, physical iPhone or native-equivalent speed claim is established. Production installation remains the user's BRAT pull after release.
