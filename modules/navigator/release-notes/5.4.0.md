# TPS Notebook Navigator 5.4.0

Released: 2026-08-03

Minimum Obsidian version: 1.11.0

Public API version: 3.3.0

## What changed

- Adds explicit **Note properties** and **Line properties** sources to compatible grouping surfaces. Native notes always
  use their own frontmatter; GCM task, bullet, and heading rows can use only their exact authored inline fields. In Line
  mode, a blank or missing value stays in **No value** and never falls back to the containing note.
- Adds calendar-day property grouping alongside exact-value grouping. Exact datetimes remain distinct by default; day
  grouping buckets authored timestamps by local `YYYY-MM-DD`, orders valid groups chronologically, and leaves blank or
  invalid values in the trailing **No value** group.
- Adds source-backed creation for Checkboxes, Bullets, Headings, Code blocks, Callouts, Blockquotes, Tables, and Web
  links. Today's Daily Note is the default target; settings can instead select the active note or a specific Markdown
  note. A missing Daily Note is created with the configured folder, format, and template, and an existing blank target
  accepts the scaffold before insertion. Checkbox creation delegates to GCM's canonical task pipeline.
- Adds **Web links** as a fixed searchable Type. A bounded local Markdown scan indexes authored HTTP(S) Markdown links,
  angle autolinks, and bare URLs without network requests. It excludes frontmatter, comments, hidden TPS carriers,
  images, and code; exposes only `scheme://host`; and re-resolves the current source before opening the owning note.
- Property sorting gives exact GCM task, bullet, and heading fields precedence over owning-note frontmatter, including
  canonical task status and scheduled values.
- Public API 3.3.0 adds `types.webLinksId`, note/line exact-value grouping encodings, and note/line calendar-day
  grouping encodings. Existing Type ids and note-property grouping encodings remain compatible.

## Compatibility and migration

- This is a backward-compatible feature release with no settings, note, or cache migration.
- Existing saved views continue using note-frontmatter grouping until Line properties is explicitly selected.
- Minimum supported Obsidian remains 1.11.0.
- Generic Line-property grouping requires TPS Global Context Menu 1.18.0. File-backed and Navigator-owned cached-range
  Types remain available when GCM is absent.

## Validation

- Focused coverage exercises exact/day grouping, top-down values, missing values, line-only semantics, native-note
  frontmatter, mixed-search open/close transitions, public snapshots, settings normalization/persistence, Daily Note
  creation and templates, blank targets, source insertion/focus, GCM checkbox delegation, and Web-link privacy,
  exclusions, caching, searching, and activation.
- Full suite: 229 test files and 2,547 tests passed on Node 24. TypeScript, Prettier, ESLint, stylesheet, TPS source
  namespace, operational-identity, and artifact-identity gates passed; ESLint reported no errors and only the
  repository's existing deprecated Kind-compatibility warnings.
- The final production-mode build deployed only the shipped plugin artifacts to **Obsidian Plugin Test Vault**. The
  plugin was reloaded there for creation, Web-link, and grouping smoke checks. Deployment preserved runtime-owned
  `data.json`; the reload advanced only its expected `lastShownVersion` acknowledgement to 5.4.0, and every temporarily
  changed user setting/view was restored. Production was not accessed.

## Known limitations

- Line-property grouping applies to GCM-backed Checkboxes, Bullets, and Headings. Navigator-owned range rows do not
  invent inline metadata, and native note rows always use frontmatter.
- The Web-link scanner is local and deliberately bounded by the shared per-file read limit and a 10,000-link per-file
  guard. It performs no network requests and searches only sanitized origins, not URL paths or page contents.
- Creation is available for the source-backed text Types listed above. Canvas, Drawings, PDFs, Images, Audio, and Video
  retain their existing file workflows.
- Desktop UI flows are verified in the isolated test vault. Mobile-specific layout and controls are covered by the
  shared markup/CSS implementation and automated tests; this release is not claimed as a real-device iOS test.
