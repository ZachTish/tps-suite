# TPS Notebook Navigator 7.0.11 — Skip unrelated calendar refreshes

Creating or renaming an ordinary Markdown note could invalidate Navigator's custom calendar day cache. With a year view
open, each such event resolved every date again even though the note could not be a calendar note. In Notebook Navigator
calendar mode, the event check now skips Markdown paths outside the configured calendar root. When every enabled note
pattern starts with a standalone year folder token (`YYYY`, `gggg`, or `GGGG`), it also skips paths whose first relative
segment has no decimal digit. The installed year-first patterns therefore skip ordinary `Inbox` changes.

The filter may refresh for an unrelated note under a numeric folder, such as `2026/Project.md`. It also refreshes
conservatively for non-year-first custom patterns. This preserves create, delete, and rename invalidation for valid
Moment patterns whose generated paths do not strictly parse back into their original dates. Renames check both old and
new paths; folder moves, Markdown extension changes, and Daily Notes integration retain their existing behavior. GCM API
reannouncements after unrelated metadata edits leave the independent custom calendar alone.

This backward-compatible performance patch adds no setting, cache, watcher, writer, or note migration. Minimum Obsidian
remains **1.11.0**. It was tested in the isolated Test vault; the user can install the release in production through
BRAT.

## Validation

- Focused regressions cover unrelated `Inbox` create/rename/delete bursts, generated day/week/month/quarter/year paths,
  numeric-folder extra refreshes, literal-first patterns, localized digits, folder moves, renames in both directions,
  Markdown extension changes, and retained Daily Notes behavior.
- All 53 focused and 3,250 full repository tests pass. TypeScript, locale, namespace, artifact, and operational-identity
  checks pass. Full ESLint reports zero errors and 26 advisory warnings, including two from the test's direct Moment
  import.
- Before the change, an installed Test-vault year view performed **372 day-target lookups across 365 dates** after an
  unrelated Inbox note creation; an unrelated rename caused another **372**. The probe kept the Test window foreground
  and its temporary fixture was archived. The rename also triggered title/frontmatter rewrites, so its total lookup
  count includes other consumers.
- The final production build deployed `main.js` to the Test runtime. A guarded plugin reload loaded 7.0.11; Navigator
  `data.json` remained byte-identical. With the installed left-sidebar September calendar visible, one unrelated Inbox
  create and rename each caused **zero** day-path lookups. This differs from the earlier right-sidebar year-view probe,
  so those counts are not a same-view latency comparison. The QA note was moved directly to `_archive`; an existing July
  20 daily note still opened from the calendar. Calendar visibility and the original note selection were restored.

Physical iPhone performance and cold-start timing are not measured by this calendar-specific patch.
