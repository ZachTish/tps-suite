# TPS Notebook Navigator 5.21.0

## Aggregate Tags and property keys

- Selecting the top-level **Tags** row shows every visible Markdown note and automatically groups the list by visible
  tags. Untagged notes receive their own group; hidden-tag visibility and separate/combine multi-value settings remain
  authoritative.
- Attached task/provider rows participate through their own tags rather than inheriting their source note's first
  rendered tag group.
- Selecting a top-level property key shows every note that contains the key, whether the value is populated, blank, or
  YAML `null`. Value rows remain exact filters, while the key row groups by all values and includes a **No value**
  bucket.
- Automatic **Untagged** / **No value** placement follows **Folder grouping: current folder files at bottom** when the
  scope has no explicit no-value override. Manual ordering stays within the required aggregate groups.
- Aggregate scopes hide the descendants control because their result set is already complete.

## Blank-key drag and compatibility

- Dropping a Markdown note on a property-key row writes and retains `key: null`, including with a compatible GCM
  property API enabled. Concrete value drops retain their existing typed behavior; task-line drops still require a
  value.
- The former UI-owned Tags selection migrates once to the new all-note collection. Existing tagged-only shortcuts and
  API navigation remain available as the compatibility **# Tags** scope.
- Reserved virtual collection paths cannot be created, renamed, deleted, or assigned as real tags.
- Public API 3.5.0 adds `tagCollections.allId` and `groupBy: 'tags'`. File-backed Types can use note-tag grouping;
  line-backed Types reject it because they render source rows rather than note instances.

This is a backward-compatible feature release. It changes no note schema or synced setting key and requires no note
migration. The local content index rebuilds once so cached blank-property presence is refreshed. Minimum supported
Obsidian remains 1.11.0.
