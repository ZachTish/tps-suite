# TPS Notebook Navigator 4.8.0

## Intent

Let TPS integrations own useful actions at the Type-collection level, including collections that currently contain no
rows, without teaching the Navigator about provider-specific creation, capture, refresh, or configuration workflows.

## Changes

- Adds `menus.registerTypeMenu(...)` in additive public API 2.9.0 for built-in, dynamic Kind, and externally registered
  Type collections.
- Supplies each callback with a frozen `{ addItem, typeId, descriptor }` context. The descriptor is defensively copied
  from the current catalog snapshot and includes optional provider ownership fields where applicable.
- Routes desktop right-click and native mobile long-press through the same collection handler. Existing provider-row
  actions and the Types/Kinds container menus retain their prior behavior.
- Revalidates the selected Type against the latest public snapshot at menu-open time. Removed collections, empty
  builders, and failed item initializers never open a blank menu; thrown and rejected failures are isolated and delayed
  additions are ignored.
- Keeps registrations runtime-only and disposable. No callback, provider option, or menu state is persisted.

## Compatibility and migration

- Backward-compatible minor release; no settings, note-data, or persistence migration.
- Public API advances from 2.8.0 to 2.9.0.
- Minimum supported Obsidian version remains 1.11.0; mobile remains supported.
- Existing integrations require no changes. Consumers must register a Type-menu callback before a collection displays
  integration-owned actions.

## Validation

- Focused regressions cover immutable exact contexts, defensive descriptor copies, registration disposal, thrown and
  Promise-returning callbacks, failed item initializers, no-empty behavior, stale/unregistered Types, and
  public/internal API exposure.
- Navigation rendering tests cover built-in Checkboxes, dynamic Kind, and external-provider Type ids, while preserving
  the Types root section menu and the menu-free Kinds container.
- The complete suite passes: 208 Vitest files and 2,208 tests, plus Prettier, ESLint, TypeScript, stylesheet, source
  namespace, artifact-identity, and production-mode build gates.
- Live Obsidian 1.12.7 QA in the isolated Plugin Test Vault confirmed the 4.8.0 release panel, selected Checkboxes
  through public Type navigation, opened and ran a temporary runtime-only `QA Type action: Checkboxes` from the
  collection row, disposed it, confirmed the row no longer opened an empty menu, and restored the original folder
  selection.
- The deployed test runtime is byte-identical to the release artifacts. Runtime-owned `data.json` retained its inode and
  was not replaced; the plugin updated only its normal `lastShownVersion` state during the verified release-panel
  reload.

## Known limitations

- This release provides the collection-action host surface; each provider or companion TPS plugin decides which actions
  to register. Navigator does not invent generic create/capture behavior for an unknown Type.
- The Types and Kinds container rows are organizational headers and intentionally do not invoke Type collection hooks.
- Builders must add items synchronously. Async work belongs in item `onClick` handlers, and actions that depend on a
  collection still existing should revalidate the opaque `typeId` when clicked.
