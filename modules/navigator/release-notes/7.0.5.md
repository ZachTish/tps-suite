# TPS Notebook Navigator 7.0.5

Tested in Obsidian Plugin Test Vault and ready for the user's BRAT pull. This release does not establish production installation or native-equivalent performance.

This backward-compatible patch stops rebuilding all searchable names when editing or renaming a note causes the current list to reorder. The existing name map now reconciles membership and reuses unchanged entries; the existing metadata event updates only its affected note. Actual getter/API/settings replacement still rebuilds names. File identity is retained in each existing entry so same-path replacements do not inherit stale names or aliases.

Already-available Obsidian metadata is used for changed/new entries, preserving fresh configured titles even when the persisted index still has the old title at the same file mtime. No new cache, observer, timer, writer, setting, schema migration or public API is introduced. Candidate selection, sorting, pinning, grouping, exclusions and note opening remain unchanged. Minimum Obsidian remains 1.11.0; desktop and mobile support is unchanged.

## Validation

- Failing-before regression: 1,000 notes and 20 body-only metadata events plus modified-order array refreshes performed 20,020 name inspections on 7.0.4. The corrected hook requires 20 changed-file inspections, no full-list name rebuilds and no membership-refresh metadata lookups.
- Regression coverage includes aliases and title changes, reordered arrays, additions/removals, rename events arriving before updated membership, same-path recreation, resolver/metadata-source replacement, cleared/reactivated search, Omnisearch and same-mtime configured-name freshness. The stale configured-name case was also reproduced against the old Storage getter.
- Node 24.19.0 / npm 10.9.2 validation: 26 focused checks and all 3,189 tests in 275 files passed. Full ESLint has zero errors and the existing 24 advisory warnings; scoped final lint, formatting, namespace, artifact and operational-identity checks passed.
- The separate versioned production build passed TypeScript and locale checks. The same artifact was deployed and explicitly reloaded only in Obsidian Plugin Test Vault. A final normal build after documentation updates verified byte-identical artifacts and reported the test runtime unchanged.

## Installed test-vault verification

The 2026-09-27 comparison kept GCM 3.6.5 and the internal `QA` text query unchanged. Operation counts include the existing display work surrounding the changed note.

| Metadata accesses per body edit | About 22,071 | First 1,471; warm 713–714 |

All six body-edit captures preserved body content and search state, with one fixture modify event each, no API publications and no blocked query calls. All twelve title saves selected the current title, preserved the body and produced exactly one modify plus one rename, with the final title and filename matching. After-change captures stayed visible and focused, with no observed long tasks or API publications.

Median title-writer/two-frame visible-update times changed from 138.2/150.5 ms to 123.95/137.45 ms. One baseline sample lost foreground focus and was excluded from the timing comparison. These small samples are descriptive; the operation-count reduction is distinct from elapsed UI time and does not establish native-equivalent performance.

Actual toolbar/preview interaction also passed: Navigator's new-note button opened the configured preview with Untitled selected; typing a title and Enter updated the filename and focused the body; typing body text and dismissing preserved it exactly once. The flow had one create, two modifies (title and body), one rename, matching final title/filename, no writes outside its fixture, unchanged probe settings and restored instrumentation. The initial QA setup incorrectly expected a folder selection instead of the existing root-plus-folder-query state; correcting that guard required no plugin change. Four exact QA folders, including the empty setup fixture, were moved directly to the test vault archive. Six runtime settings files remained byte-identical; Navigator changed only its existing lastShownVersion marker from 7.0.1 in the saved baseline to 7.0.5, with every other value unchanged. No settings migration was performed.

## Limits

Use GCM 3.6.5 or newer for the combined edit improvement: older GCM builds may announce API replacement on ordinary edits, which legitimately invalidates the resolver and limits name reuse. This does not add a hard API minimum or change settings.

The fix removes redundant internal name-search work. Existing candidate collection, genuine title/property/date sorting, grouping and visible-row work remain. Test-vault results do not establish cold-start, production, physical iPhone or native-Obsidian-equivalent performance. Production installation remains the user's BRAT pull.
