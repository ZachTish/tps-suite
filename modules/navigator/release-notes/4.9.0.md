# TPS Notebook Navigator 4.9.0

## Intent

Let TPS integrations add their own actions to the actual source-backed rows rendered by Navigator without exposing the
host menu, provider mutation callbacks, or internal GCM records.

## Changes

- Adds `menus.registerRowMenu(...)` in additive public API 2.10.0 for attached rows and Notes, Checkboxes, Bullets,
  Headings, dynamic Kinds, provider-owned Type rows, and augmenting provider rows.
- Supplies each action with a frozen current-file target containing provider/row/kind identity, label, source path,
  optional zero-based source line, selected Type id, and immutable checkbox presentation.
- Adds an optional pure, synchronous `supports(target)` filter. Registration and idempotent disposal refresh open
  virtualized lists immediately so matching action affordances track the live registry.
- Composes row-owner actions first and registered actions afterward through one desktop right-click, native mobile
  long-press, and keyboard-accessible **More actions** path.
- Re-resolves the source file and matching registrations when the menu opens. Deleted sources and stale registrations do
  not consume the native context-menu event.
- Keeps builders and real `MenuItem` initializers synchronous and fail-closed. Promise-returning builders invalidate the
  attempted menu even when they add before their first `await`; rejections are observed, delayed additions are ignored,
  and a failed item initializer cannot expose a blank or partially configured native menu.

## Compatibility and migration

- Backward-compatible minor release; existing providers and integrations require no changes.
- Public API advances from 2.9.0 to 2.10.0.
- Minimum supported Obsidian version remains 1.11.0; mobile remains supported.
- Registrations are runtime-only. No settings, callback state, note data, or migration is added.

## Validation

- Focused regressions cover immutable target delivery, visible optimistic checkbox state, registration
  revision/disposal, pure filters, stale sources and registrations, row-owner ordering, separators, native
  submenu/object identity, and pointer/More entry points.
- Failure coverage includes throwing and Promise-returning filters/builders/item initializers, resolved and rejected
  thenables, sync-before-`await`, delayed additions, host failures, empty menus, and event consumption only after
  display.
- The complete suite passes: 208 Vitest files and 2,232 tests, plus Prettier, ESLint, TypeScript, stylesheet, source
  namespace, artifact-identity, and production-mode build gates.
- Live Obsidian 1.12.7 QA in the isolated Plugin Test Vault confirmed version 4.9.0, the visible **Types** hierarchy
  with Notes, Checkboxes, Bullets, Headings, and Kinds, Checkboxes results, and exact-source row activation.
- A temporary runtime-only registration appended `QA row action` after the selected row's native GCM actions. Clicking
  it delivered the exact current `TFile`, zero-based line 0, `structural:task` Type id, visible checkbox state, and
  frozen target/checkbox objects; disposal removed the action immediately. The registration and console globals were
  removed.
- The deployed test runtime is byte-identical to the release artifacts. Runtime-owned `data.json` retained its inode and
  only advanced its normal `lastShownVersion` field to 4.9.0 during the verified release-panel reload.

## Known limitations

- This release provides the generic host surface. Companion TPS plugins decide which rows they support and which actions
  they register; Navigator does not invent provider-specific mutations.
- `sourceLineNumber` is a display locator and may become stale after an edit. Mutating integrations must use their own
  current index or locator to re-resolve a line when the item is clicked.
- Builders, filters, and item initializers must stay synchronous. Put asynchronous work inside `onClick` handlers.
