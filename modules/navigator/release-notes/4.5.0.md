# TPS Notebook Navigator 4.5.0

## Intent

Complete the first public control loop for first-class Types: integrations can discover structural and dynamic Kind
collections, wait for an authoritative catalog, and navigate to a collection without hardcoding GCM conventions or
dispatching internal state.

## Changes

- Adds a frozen, provider-neutral `types` catalog to public API 2.6.0. It exposes stable Notes, Checkboxes, Bullets, and
  Headings ids; Kind id build/parse helpers; syntax validation; immutable discovery snapshots; immediate subscriptions;
  and terminal readiness handling.
- Adds `navigation.navigateToType(typeId)`. It opens and waits for the TPS Navigator, validates the id, expands
  **Types** and **Kinds**, records ordinary selection history, preserves navigation focus, and requests the collection
  into view.
- Routes navigation-row clicks and back/forward Type restoration through the same pure resolver used by the public API.
- Treats a complete `ready` catalog as authoritative while preserving valid provisional ids through `loading`,
  `unavailable`, and `error` states. A temporary GCM startup or outage therefore cannot erase restored history.
- Keeps catalog DTOs independent of GCM internals: no entity records, note paths, task payloads, mutable maps, or
  ambiguous pre-visibility counts cross the public boundary.
- Tracks the Types setting live, shares one underlying entity-index subscription across all API listeners and readiness
  waiters, and closes that subscription safely on plugin unload.

## Compatibility and migration

- Backward-compatible minor release; no settings or note-data migration.
- Public API advances from 2.5.0 to 2.6.0. All 2.5.0 methods and result shapes remain unchanged.
- Minimum supported Obsidian version remains 1.11.0.
- TPS Global Context Menu 1.15.0 remains the tested Entity Index v3 and task-action baseline. Missing or incompatible
  GCM still fails closed and reports catalog availability without affecting ordinary file navigation.

## Validation

- Focused tests cover disabled/loading/ready/unavailable/error catalog mapping, deep immutability and cache identity,
  immediate and shared subscriptions, subscriber-error isolation, idempotent cleanup, readiness success/failure,
  structural and Kind helpers, ready-only missing-id and stale-history rejection, provisional selection, ancestor
  expansion, focus, history, and TYPE scrolling.
- Public declaration-consistency tests cover the new DTOs, namespace members, and navigation signature. View-controller
  tests cover successful, rejected, unavailable, and not-ready Type navigation.
- The complete 200-file, 2,120-test suite, formatting, ESLint, TypeScript, stylesheet, source namespace, final artifact,
  and production-mode build gates pass for the released artifact.
- The final build deployed only `main.js` and `manifest.json` to the isolated test vault. The pre-reload runtime
  settings file was byte-identical; reload changed only its normal `lastShownVersion` marker from 4.4.0 to 4.5.0.
- Obsidian 1.12.7 reload rendered the Types navigation section, opened Bullets, and opened a selected bullet at its
  owning note and line. Checkboxes rendered live custom task markers. A final developer-console smoke returned API
  `2.6.0`, a `ready` 28-descriptor catalog, and `true` for public navigation to Checkboxes.

## Known limitations

- The catalog intentionally omits counts because raw entity-index counts and post-visibility Navigator counts have
  different meanings.
- External row providers can augment an existing selected Type collection, but public API 2.6.0 does not yet let them
  define new top-level Type collections. A generic provider registry remains the next architectural milestone.
- Types remain virtual records and do not participate in file multi-select, drag, rename, pinning, grouping, or note
  creation.
