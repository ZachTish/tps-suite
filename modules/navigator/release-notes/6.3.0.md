# 6.3.0 — Shared note creation opening

Navigator's new Markdown notes can now use the same editable preview, open, or stay preference as Bases and Calendar through TPS Global Context Menu 2.5.0+.

- Folder/tag/property New note actions and the Navigator command finish their metadata/sort work before the shared presentation handoff. Tag-note creation and ordinary Markdown folder-note creation also participate.
- **Appearance & behavior → After creating a note → Configure note opening** leads directly to GCM. The legacy new-tab key is retained for migration and older/disabled-GCM fallback.
- Explicit new-tab and special folder-note destinations remain overrides. Non-Markdown resources, periodic note navigation, independent Templater commands and background creation retain their prior behavior.
- A provider error preserves the created note without attempting a second opening. Existing TPS/upstream namespace separation is unchanged.

Validation: all 3,071 tests across 270 files passed; lint has no errors and 24 pre-existing warnings. Separate build passed strings, locale, type and artifact checks; test-only deployment and reload passed. Live Navigator New note displayed the name-focused preview while the embedded Calendar stayed active; the settings handoff reached GCM. Dependency cache preparation produced byte-identical tested artifacts. Test preferences were restored and fixtures archived.

Known limitations: GCM 2.5.0+ is required for the shared behavior; older/disabled GCM keeps the legacy opening setting. Physical iPhone acceptance remains pending.

Backward-compatible minor feature release. Minimum Obsidian: **1.11.0**. Tested in **Obsidian Plugin Test Vault**, ready for the user's BRAT pull. This release has not been installed in production by the agent.
