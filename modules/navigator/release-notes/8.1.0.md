# TPS Notebook Navigator 8.1.0 — Nested property values

Property values containing `/` previously appeared as flat rows such as `entity/food/transaction`. Plain slash-delimited values now form expandable rows under their property key: **kind → entity → food → transaction**. An intermediate row is a virtual grouping node unless a note has that exact value. The existing Include descendant notes preference controls whether selecting a parent includes nested values; exact leaf selection still targets only that value. Frontmatter and stored property-node IDs are unchanged.

Nested rows work with counts, sorting, shortcuts, menus, keyboard navigation, programmatic reveal, list breadcrumbs, filtering, drag/drop and note creation. Links and URLs containing slashes remain single values. This adds no settings, writer, migration, watcher, or additional vault scan. Obsidian **1.11.0+** remains supported. It is a backward-compatible feature release.

## Validation

- All 3,246 tests passed across 280 files. The new regression cases cover tree construction and selection, exact/subtree search, sorting/counts, keyboard and programmatic navigation, shortcuts, menus, creation and drag/drop paths, and a 1,000-note single-pass indexing check.
- ESLint passed with zero errors (26 existing warnings); style lint, TPS namespace, artifact, and operational-identity checks passed. A separate production-mode build deployed the versioned artifact to the Obsidian Plugin Test Vault.
- After a full test-vault app reload, `kind: entity/food/recipe` and `kind: entity/food/transaction` appeared under **kind → entity → food**. Selecting `entity` generated `.kind^=entity` and displayed both descendants plus an existing `entity/food` note; selecting `recipe` generated `.kind==entity/food/recipe` and displayed only the recipe note. Temporary QA notes were moved from Inbox directly to `_archive` afterward.
- The test-vault runtime's `data.json` was preserved by deployment; Obsidian updated its own Navigator state during the reload and UI interactions. iPhone UI was not separately exercised; the shared responsive tree and search paths are covered by the same code and tests.

The change does not rename or rewrite existing property values. A property note still matches the full value path rather than only its last segment. A link alias and a plain value that normalize to exactly the same slash path retain one canonical row and both note memberships; in that rare collision, the row's placement depends on which value the index encounters first. This release was tested in the test vault and is ready for the user's BRAT pull.
