# TPS Notebook Navigator 7.0.2

Ordinary note navigation no longer resolves every note's title and aliases to build an unused search map. Empty searches, structural filters without name clauses, and Omnisearch now skip that work and its metadata listener. This removes a repeated full-vault GCM identity-inspection pass from list refreshes.

Text and alias searches still use the existing map, including excluded name clauses and metadata updates to individual notes. Clearing search releases the listener; starting another name search reads current names. Visible titles, title sorting, note opening, and the existing GCM identity checks retain their behavior. There are no settings, APIs, note-data migrations, new caches, or pollers.

Creating from a tag or property now sends that facet in Obsidian's initial Markdown creation payload. This removes the empty-file-then-frontmatter-write sequence, which exposed incomplete notes to creation listeners and could still open a note after facet assignment failed. Nested tags, property values and null-valued property key roots keep their existing meaning. Default parent selection, unique names, Obsidian creation hooks, manual sorting and the shared GCM opening route remain intact; no repair or retry is introduced.

This backward-compatible fix is a patch release. Minimum Obsidian: **1.11.0**. Tested in **Obsidian Plugin Test Vault** on Obsidian 1.14.2 and ready for the user's BRAT pull. Production was not updated by this release task. Physical iPhone acceptance remains outstanding.

## Validation

- 23 focused search checks and the full suite: **3,157 tests in 273 files passed**.
- Operation-count coverage: 1,000-note startup and repeated empty-search/list refreshes make zero search-name inspections and zero search-metadata reads. Active name search builds once; one metadata change adds one lookup. Tests preserve alias matches, negative clauses, structural-only search, Omnisearch, and clearing/reactivating search.
- Creation regression: before the fix, both nested-tag and kind-property create observers received empty content. After the fix they receive their complete facet in the first payload, with zero second frontmatter writes. Null-valued property roots and failure-without-presentation are covered by 21 focused creation/property/tag-note checks.
- ESLint: zero errors, 24 existing advisory warnings. TypeScript, string/locale, namespace, operational identity and artifact identity checks passed.
- The final versioned production-mode build deployed only to the test vault, followed by a targeted Navigator reload. A separate final build after documentation changes confirmed byte-identical artifacts and preserved runtime settings.
- Installed creation QA used the real Navigator file-system operations and GCM registry for tag, property and folder creation: each made one Markdown creation call, one vault create and one presentation call, with no post-create frontmatter/process/modify write from the creation route. Initial API/vault payloads already contained the selected nested tag or synthetic property; metadata parsed them correctly. Immediate test body edits survived 4.5 seconds of settling and all three routes used configured preview. Small-sample durations were 233 / 454 / 123 ms. Fixtures were created in Inbox and archived directly; wrappers, list state and original settings were restored. This checks installed APIs, not toolbar gestures or physical iPhone interaction.

## Installed measurements and limits

The installed comparison used the same Navigator selection/search state, 10,256 indexed notes, and four opens of two unchanged notes. Results below include both **GCM 3.6.2 and Navigator 7.0.2**; they are not an isolated timing attribution to this release.

| Measurement | Before | After |
| --- | --- | --- |
| GCM identity inspections | 72,849 | 448 |
| Four opening-call durations | 15 / 550 / 504 / 19 ms | 20 / 29 / 24 / 20 ms |
| Maximum observed timer delay in the backgrounded test window | 2,900 ms | 904 ms |

The test window was backgrounded with timer throttling enabled, so the 904 ms timer delay does not establish a main-thread CPU stall. A separate warm Navigator reload took 266 ms with zero vault read, cachedRead, process or modify calls; an eight-second passive CPU capture was predominantly idle and attributed less than 4 ms to JavaScript. This reload measurement was also backgrounded and covers plugin reload only, not full Obsidian startup.

A separate post-fix repeat confirmed the test window was visible and focused. Four opening calls measured **42 / 11 / 15 / 11 ms**, with **594 GCM identity inspections**, at most **18 ms drift on a 100 ms timer**, and **no PerformanceObserver long tasks** during the roughly six-second capture. This foreground repeat is additional validation, not a foreground before/after baseline.

These checks do not prove that every performance issue is solved. Opening-call durations are not an end-to-end rendering guarantee, and test-vault measurements do not establish production, cold-start, or physical iPhone performance. The release preserves existing behavior while removing the demonstrated unused full-list calculation.
