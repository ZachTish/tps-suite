# TPS Notebook Navigator 7.0.3

Tested in Obsidian Plugin Test Vault and ready for the user's BRAT pull. This release does not establish production installation or native-equivalent performance.

This patch keeps generated icon/color updates out of the full list indexing path. Preparing newly visible rows while scrolling previously changed the display-name callback and rebuilt the full selection, text/alias index, date groups and virtualizer inputs even though names and membership had not changed.

The existing presentation revision now refreshes visible rows explicitly. Non-manual property sorting and property grouping still respond when generated values change. Title metadata, aliases, GCM API replacement, settings and actual list changes retain their existing update paths. Manual ordering and authored values remain authoritative.

No settings, defaults, public APIs, persistent state, notes or minimum compatibility change. No additional cache, poller, listener, writer or retry is added. Minimum Obsidian: 1.11.0; desktop and mobile remain supported.

## Validation

- Focused operation-count regression: one mount plus 20 appearance batches over 1,000 notes changed from 21 whole-selection derivations to one, with no additional display-name inspections. Empty, text and tag queries retain list-item identity. Storage startup and optional provider boundaries are mocked; the Storage provider, list/search hooks, sort and grouping logic execute.
- Actual title metadata, one-file name updates, aliases, API lifecycle/settings refresh, generated appearance, property sort/group/count updates and manual-property exclusion are covered.
- The 26 focused checks and full 3,165 tests in 274 files passed. ESLint: zero errors, 24 existing advisory warnings. Source TypeScript, namespace and operational-identity checks passed.
- The production-mode build passed locale/type/identity checks. The tested artifact was deployed and Navigator reloaded only in the test vault; a separate final build after documentation updates verified byte-identical runtime artifacts and preserved runtime settings.

Installed test-vault diagnostic comparison, 7.0.2 → 7.0.3:

| Action | Metadata lookups | Identity inspections | Median sampled time |
| --- | ---: | ---: | ---: |
| 10 appearance notifications, empty search | 103,170 → 640 | 360 → 320 | 50.75 → 19.7 ms |
| 10 appearance notifications, `QA` text search | 219,200 → 620 | 103,630 → 310 | 409 → 18.8 ms |
| 12 programmatic scroll steps | 339,517 → 218,905 | 1,819 → 1,889 | 80.4 → 58.05 ms |

Appearance notifications were synthetic but exercised the installed full list and real integration. Scroll steps used the actual rendered list; neither test simulated physical gestures or established native-Obsidian acceptance. The search had 670 rows in both runs; empty lists contained 11,009 and 11,011 rows. Both captures recorded zero concurrent vault events and no PerformanceObserver long tasks. Counts and timings measure different aspects and should not be generalized to cold startup, all interactions, production or iPhone performance.

The operation counts are not a claim that overall interaction latency matches native Obsidian. Property ordering can still rebuild when the coarse GCM presentation revision changes, and real membership/name/date changes still require their owning list refresh. Production installation and physical iPhone acceptance remain separate from test-vault QA and publication.
