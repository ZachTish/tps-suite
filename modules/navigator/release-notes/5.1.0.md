# TPS Notebook Navigator 5.1.0

Released: 2026-08-02

Minimum Obsidian version: 1.11.0

Public API version: 3.1.0

## What changed

- Adds **Code blocks**, **Callouts**, **Blockquotes**, and **Tables** as flat built-in collections immediately after
  Headings in **Types**.
- Uses Obsidian's root-level `CachedMetadata.sections` as the parser authority. The index does not read note bodies,
  performs a cache-only startup build, updates one note at a time after metadata changes, and removes or rekeys rows
  immediately when a note is deleted or renamed.
- Presents each result with the ordinary file-list visual language, a restrained structure-specific icon, the owning
  note, and its source line or range. Plain search, pointer selection, keyboard navigation, source opening, and
  registered row-menu actions work through the existing transient-row path.
- Revalidates the current metadata cache before opening. A row with an existing block id follows that id after movement;
  a stale range-only locator fails closed rather than opening the wrong content.
- Separates Navigator-owned Markdown availability from the optional GCM Entity Index, so a GCM failure affects only
  Checkboxes, Bullets, and Headings.
- Adds the backward-compatible API getters `codeBlocksId`, `calloutsId`, `blockquotesId`, and `tablesId` in API 3.1.0.

## Compatibility and migration

- This is a backward-compatible feature release. Existing Type ids, settings, providers, menus, and navigation contracts
  are unchanged.
- No settings migration or note-content migration is required.
- The minimum supported Obsidian version remains 1.11.0.

## Known limitations

- Obsidian documents `CachedMetadata.sections` as root-level Markdown blocks. Nested syntax is listed only when Obsidian
  emits it as a separate section; the Navigator does not add a second parser to discover hidden nested structures.
- Structure rows are transient source locations, not fake files. They do not yet participate in file multi-select,
  pinning, rename, persistent selection, or drag and drop. Drag is deferred until moving a range can preserve Markdown
  syntax and stable locators safely.
- Structure labels intentionally use the owning note and starting line because the metadata cache does not expose block
  text or fenced-code language without reading the note body.

## Validation

- Focused tests cover the four-type whitelist, unsupported-section rejection, root-level nesting behavior, Excalidraw
  exclusion, zero note-body reads, incremental update/delete/rename lifecycle, range normalization, stale-locator
  rejection, block-id movement, independent GCM/Markdown availability, row range labels and icons, public ids, and
  uncapped built-in rows. A deferred-query regression also proves that a late GCM result cannot roll back newer Markdown
  metadata.
- Full suite: 219 test files and 2,410 tests passed.
- TypeScript: `tsc --noEmit --skipLibCheck` passed.
- The final production-mode rebuild deployed only byte-changed `main.js` to the isolated test runtime; `manifest.json`
  and the complete `styles.css` were already byte-identical. Source and runtime artifacts matched byte for byte.
- Obsidian 1.12.7 was reloaded in **Obsidian Plugin Test Vault**. Live UI QA confirmed the flat order and native
  styling, nonzero counts, owning-note/line labels, path/range context, path search, correct Callout source opening, and
  one root-level Code block result for a fixture whose Callout contained a nested fence. The temporary fixture was then
  moved directly to `_archive`.
- The test runtime `data.json` inode was preserved across deployment. No production vault was inspected or changed.
