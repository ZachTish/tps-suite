# TPS Notebook Navigator 4.11.0

## Intent

Make TPS-rendered rows behave like real, controllable Navigator results while keeping them transient, source-backed, and
strictly separate from native file selection and upstream Notebook Navigator state.

## Changes

- Attached and Type-backed rows now share one first-class selection cursor with native list navigation. Pointer
  selection, Arrow/Home/End/Page traversal, and Enter activation work without fabricating `TFile` objects or persisting
  row state.
- Public API 2.12.0 adds immutable `selection.getCurrentRow()`, `row-selection-changed`, and guarded
  `navigation.focusRow(...)`. Stale, filtered, removed, renamed, or deleted rows fail closed.
- Public API 2.13.0 adds the pull-based `list` namespace. Consumers can inspect the first mounted TPS view's current
  navigation scope, truthful immediate/applied search state, requested/effective provider, presentation, and composed
  renderable row order without receiving callbacks or continuously cloned collections.
- `list.setSearch(...)` applies one validated search request immediately. Asynchronous Omnisearch snapshots identify the
  exact query that produced their current rows, and an unavailable Omnisearch request remains visible as requested while
  the effective provider reports the internal fallback.
- `list.setPresentation(...)` validates a complete per-scope sort/group/display update before saving, preserves
  unrelated appearance settings, and restores the prior live settings if persistence fails.
- Provider rows expose valid current-selection accessibility state. Primary row keys continue to bubble to list
  navigation; checkbox and menu controls retain isolated keyboard behavior. Rejected stale selection blocks activation
  and optimistic mutation, and event envelopes are frozen for all listeners.
- The default-on **Types** hierarchy remains Notes, Checkboxes, Bullets, Headings, and dynamic Kinds. Notes open their
  note; structural entities re-resolve and open the exact current source line. Current rows use the shared
  desktop/mobile menu path, including GCM's exact note actions when GCM 1.16.0 is installed.
- A new operational-identity gate scans committed maintenance guidance so future work cannot accidentally deploy,
  reload, or edit upstream Notebook Navigator while the co-installable TPS fork is targeted.

## Compatibility and migration

- Backward-compatible minor release; public API advances from 2.11.0 to 2.13.0.
- Minimum supported Obsidian remains 1.11.0; desktop and mobile remain supported.
- Existing row and Type providers remain structurally compatible. New selection and list controls are additive.
- No setting key, persisted row state, note data, or migration is added.

## Validation

- All 215 Vitest files and 2,308 tests pass. TypeScript, ESLint, Prettier, stylesheet lint, CSS namespace,
  operational-identity, artifact-identity, and production-build gates also pass for the versioned candidate.
- Live Obsidian 1.12.7 test-vault QA after reload confirmed both upstream and TPS Navigator entries remain co-installed;
  Types exposes Notes, Checkboxes, Bullets, Headings, and Kinds with live counts; a Bullet opened its exact current
  source line; a Note exposed the canonical GCM whole-note menu; a Checkbox retained the task menu without duplicate
  actions; and ordinary folder navigation remained unchanged.
- Deployment kept runtime-owned `data.json` in place with the same inode and size. The plugin advanced only its own
  `lastShownVersion` marker to 4.11.0 during the verified reload; no settings file was replaced or copied. Production
  was not accessed or changed.

## Known limitations

- The public list namespace deliberately targets only the first mounted TPS Navigator view and never opens one. Callers
  receive `null`/`false` if no stable mounted view is available.
- Type collections own their row order, so their snapshot presentation is `null`; advanced file-search operators and
  Omnisearch ranking remain file-list features.
- External providers still own their activation/mutation callbacks. Public selection and list snapshots expose identity
  and presentation only.
