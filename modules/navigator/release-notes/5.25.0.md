# TPS Notebook Navigator 5.25.0

This minor release makes folder notes work at the vault root and adds convention-based tag notes without introducing
another identity field, mapping, or persisted setting.

- The vault root now supplies the preferred literal source name `Vault` to the existing folder-note pattern. The default
  `{{folder}}` pattern therefore identifies `Vault.md`, `_{{folder}}` identifies `_Vault.md`, and a fixed pattern such
  as `index` continues to identify `index.md`. A pre-existing root note based on the actual vault name remains a
  backward-compatible fallback.
- A tag note is any unique Markdown note anywhere in the vault whose basename case-insensitively matches the final
  authored segment of the tag and whose tag metadata, either frontmatter or inline, contains that exact full tag. For
  example, `Projects/Active` resolves to a uniquely matching `Active.md` carrying `Projects/Active`.
- A resolved tag note opens from its tag label, a tag shortcut, the current list header, or Enter activation. The tag
  row itself retains its normal selection and expansion behavior, and ordinary navigation modifiers continue to control
  new-tab activation. Linked labels are keyboard-focusable, and matching-note changes refresh across every navigation
  surface even when the note lives in a hidden or excluded folder.
- **Create tag note** is available from the real tag's context menu when no unique note is resolved. It creates the
  exact tag-segment filename in the configured default new-note folder and writes the exact full tag to YAML. It never
  adds a numeric suffix; an occupied path, invalid tag, or multiple matching notes fails closed.
- Folder and tag navigation notes share the existing folder-note master switch, link switch, and open-location setting.
  Folder-note templates, Type assignment, hiding, pinning, and nearest-folder-note behavior remain folder-only.
- The association is always derived from the note's current filename and tag metadata. No tag-note ID, registry, hidden
  frontmatter field, synced setting, IndexedDB record, or public API is added.
- Tag renames do not rewrite or rename notes automatically. A note associates with the renamed tag only after its
  basename and exact tag metadata satisfy the same convention.
- Right-sidebar navigation notes reuse one path-marked plugin companion across restarts and switches. The namespaced
  marker lives only in Obsidian's workspace view state, never in note frontmatter, and unrelated sidebar documents are
  not claimed or pruned.
- Public API remains 3.6.0. Minimum supported Obsidian remains 1.11.0, and no migration is required.
- Known limitation: when more than one note matches a tag, Navigator deliberately leaves the tag unlinked until the user
  removes the ambiguity.
