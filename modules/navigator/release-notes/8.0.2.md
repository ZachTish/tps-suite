# TPS Notebook Navigator 8.0.2 — Create configured list properties as lists

Creating a note from a property value previously wrote that value as a scalar in the initial Markdown file, even when
GCM configured the property as a list. The same Navigator action on an existing note already respected GCM's list type.
A property search such as `.kind=task/todo` could therefore create a note with `kind: task/todo` instead of
`kind: [task/todo]`.

New property notes now use the same configured list-type check as property drops. A selected value for any GCM list
property is published as a one-element YAML list in the initial file content, before creation observers see the note.
Key-only selection retains its empty placeholder; non-list and unconfigured properties retain scalar or boolean
behavior. The Properties tree, property shortcuts, and sole-property Filter Search all call this creation path. No
delayed writer, repair pass, settings change, schema migration, or vault scan is added. GCM must be enabled with a list
definition for list creation; without it, Navigator retains its existing scalar fallback. Minimum Obsidian remains
**1.11.0**. This backward-compatible fix is a patch release.

## Validation

- A focused red regression reproduced scalar creation for configured `kind` and `categories` list properties. The
  corrected tests verify atomic one-element arrays, no second frontmatter write, key-only null, unchanged scalar
  creation, and `.kind=task/todo` search routing and list-value matching.
- All **3,218 tests in 274 files** pass. The separate final production-mode build passed TypeScript and locale checks
  and deployed `main.js` and `manifest.json` to **Obsidian Plugin Test Vault**. ESLint passed with zero errors and 26
  existing advisory warnings. Stylelint, TPS namespace, artifact identity, and operational identity checks passed.
- In Obsidian 1.14.4 on Mac, a full Test-vault reload loaded the final 8.0.2 artifact. Navigator's actual New action
  under `.projects=nn-list-qa-20261003b` created a note in Inbox whose initial frontmatter was
  `"projects": ["nn-list-qa-20261003b"]`. The installed bundle and source bundle had identical SHA-256 hashes. Hot
  Reload alone had left the prior code in memory and produced a scalar in the first QA run, so the full reload was
  necessary. Both temporary notes were archived directly, and the temporary new-note-location setting was restored to
  its original bytes.

Physical iPhone QA and production installation have not been performed. This release is tested in the isolated Test
vault and ready for the user's BRAT pull into TishOS v0.2; the production update is separate.
