# TPS Notebook Navigator 7.0.9 — Skip unused header indexing

Navigator no longer discovers custom-header word-count consumers when no configured view can display custom groups. This removes three unnecessary full-vault scans in the tested startup. Metadata edits, renames and deletions also skip the inactive index. Normal word counts and enabled custom groups retain their existing behavior.

The existing grouping resolver covers default, appearance and sort overrides. Disabling the final custom context discards its existing snapshots; enabling a context discovers current headers, including changes made while disabled. In-place settings edits invalidate the existing grouping decision. No new cache, listener, timer, setting, schema, writer or migration is introduced.

Backward-compatible **patch**; minimum Obsidian **1.11.0**. Tested in **Obsidian Plugin Test Vault**, ready for the user's BRAT pull. Production has not been modified.

## Validation

- Three new regressions failed before the correction. All 100 focused and 3,234 full tests pass, with no failures or skipped tests.
- Tests cover 1,000-note inactive startup, 100 metadata/rename/delete bursts, counts with custom grouping off, enabling after disabled edits, in-place settings publication, active header discovery, metadata readiness, grouping overrides, folder changes and cache-only renders.
- ESLint: zero errors, 24 existing advisory warnings. Styles, locale shapes/usage, TypeScript, namespace, artifact and operational-identity checks pass.
- Separate production-mode build deployed to the test runtime; named reload and a subsequent test-window reload loaded 7.0.9 with the complete consumer suite enabled.
- Foreground startup comparison: total Markdown scans **9 → 6**, metadata lookups **265,117 → 231,209**. Stack traces identify all three removed scans as inactive custom-header discovery. Raw vault reads (422), cached reads (154), adapter reads (502) and writes (6) were unchanged. These are whole-window counts, not all note mutations or all attributable to one plugin.
- Unique visible note body and Navigator list verified. Body readiness **2,726 → 2,674 ms** in a single warm before/after pair. This is insufficient for a general latency or 80%-native-performance claim; startup still includes core indexing, Navigator hydration/list rendering and other active plugin work. Existing GCM property-panel layout shift remains outside this fix.
- Synthetic fixtures restored/archived with exact bytes; eight monitored settings files and all runtime artifacts remained unchanged during each capture. Temporary observers, wrappers, preload and debugger were removed. Release notice was dismissed normally before the measured after run.
- Test host Obsidian 1.14.2; true cold process, minimum-version runtime, physical iPhone and paired plugin-free baseline remain unverified. No production or paused-plugin changes.
