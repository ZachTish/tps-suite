# TPS Notebook Navigator 4.10.0

## Intent

Stop obsolete transient-row work as soon as the visible Navigator query changes, especially bounded GCM task scans that
could otherwise finish and mutate caches after a folder, Type, search scope, or provider revision had been superseded.

## Changes

- Public API 2.11.0 adds `NavigatorRowProviderQueryContext.signal` to `getRows(...)`. The existing
  `NavigatorRowProviderContext` remains the subscription context, so existing providers remain structurally compatible.
- Every provider invocation receives an independent signal. Scope, selected Type, search-derived paths, provider
  revision, options replacement, unregister, view teardown, timeout, and plugin unload cancel the corresponding active
  work.
- Lifecycle cancellation settles composition promptly and silently even when a provider ignores its signal. Late resolve
  and rejection paths stay observed but cannot publish or report a stale failure. A five-second timeout still reports
  one isolated provider failure and does not abort healthy siblings.
- Provider registrations capture their validated ID and are tracked by exact identity. Options changes and unregister
  cancel all active queries for that registration, stale disposers or externally mutated objects cannot affect another
  registration, invalid options cannot cancel valid work, and unload also cancels built-in work.
- The built-in GCM task provider checks cancellation between every eight-path batch. Fetched values are staged and
  committed only after the complete active pass, so cancellation cannot write positive or negative cache entries, clear
  dirty paths, alter scope state, launch another batch, or schedule a progressive refresh.
- The default-on Types hierarchy remains Notes, Checkboxes, Bullets, Headings, and dynamic Kinds. Note entities open
  their note; checkbox, bullet, and heading entities re-resolve and open the exact current source line.

## Compatibility and migration

- Backward-compatible minor release; public API advances from 2.10.0 to 2.11.0.
- Minimum supported Obsidian version remains 1.11.0; desktop and mobile remain supported.
- Existing row providers may ignore the additive signal. Cooperative providers should check it before expensive work and
  after each awaited batch.
- No setting, persisted provider definition, callback state, note data, or migration is added.

## Validation

- Focused regressions cover frozen independent query contexts, pre-abort, two-provider supersession, late resolution,
  isolated timeout, registry/Rows API options, unregister and unload cancellation, and public declaration parity.
- GCM regressions cover pre-aborted no-op behavior, cancellation during the first and second eight-path batches,
  transactional cache protection, progressive-pass suppression, and preservation of dirty paths for the next active
  read.
- The complete suite passed: 208 Vitest files and 2,263 tests, followed by Prettier, ESLint, TypeScript, stylesheet,
  source-namespace, artifact-identity, and production-build gates.
- The final artifacts were atomically deployed to the isolated test vault and reloaded in Obsidian 1.12.7. Live QA
  confirmed the default-on Types hierarchy, standalone Checkbox and Bullet collections, exact-source activation for
  both, and an unaffected ordinary folder list.
- Runtime-owned `data.json` retained inode `232880478`; only the plugin-owned release-note acknowledgement advanced to
  4.10.0. Production was not accessed or changed.

## Known limitations

- GCM task API v1 does not accept an `AbortSignal`, so already-started per-path reads may finish internally. TPS
  observes those Promises but discards their results; it cannot interrupt the foreign call itself.
- Providers that ignore the signal may continue private work after host cancellation, although they can no longer hold
  the composition open or publish late rows through TPS.
